# ТЗ: «Ценовой мониторинг: конкуренты + поставщики» (v2.0)

Статус: принято к разработке. Дата: 20.09.2026.

## 1. Общее описание

Локальное однопользовательское приложение для владельца бизнеса. Два контура данных — **конкуренты** (розничные цены, отчёт по отклонениям) и **поставщики** (закупочные прайсы, сравнение). Сбор и разбор данных, а также рекомендации выполняет **ИИ-агент (Timeweb)**; владелец подтверждает спорные сопоставления и смотрит отчёты.

**Стек:** Python 3.11+ · Streamlit · SQLite · Pandas · RapidFuzz · Plotly · интеграция с ИИ-агентом через адаптер.

**Фиксированные решения:**
- Единственная роль — **Владелец**. Без логина/пароля (локальный запуск).
- Валюта — **только рубли** (RUB), мультивалютность не поддерживается.
- **Уведомления отсутствуют** (без email/Telegram).
- Сбор и сопоставление ведёт ИИ-агент, но **только из разрешённых источников**. Ответственность за соблюдение условий использования остаётся на владельце.

## 2. Роли

| Роль | Действия |
|---|---|
| **Владелец** (единственный пользователь) | Запускает загрузки/сбор, подтверждает спорные сопоставления, смотрит отчёты и историю, управляет каталогом и источниками |
| **ИИ-агент (Timeweb)** | Собирает данные только из `approved` источников, предлагает сопоставления, выдаёт рекомендации по ценам |
| **Система** | Нормализация, хранение, расчёт отклонений, логирование. Не принимает решений в спорных зонах |

Никакой авторизации: приложение запускается владельцем локально, один экземпляр, одна роль.

## 3. Источники данных

### 3.1. Реестр источников (таблица `sources`)

Сбор разрешён **только** из записей со статусом `approved`. Поля:

- `name`, `scope` — **`competitor`** | **`supplier`** (контур данных)
- `kind` — `csv_upload` | `api` | `price_feed`
- `origin_url`, `terms_hash` (копия условий использования)
- `allowed_fields`, `usage_limits` (частота, лимиты), `min_refresh_minutes`
- `requires_attribution` — обязательно показывать название источника
- `status` — `approved` | `blocked` | `expired`; `approved_at`, `review_period_days`

**Правила:**
- Ввод источника только с приложенным документом условий и чекбоксом «Условия изучены, использование разрешено». Нет условий / прямо запрещён сбор → `blocked`.
- `review_period_days` истёк → `expired`, сбор блокируется. `requires_attribution` → источник виден в отчёте/истории всегда.
- Запуск сбора из источника запускается через ИИ-агента либо ручной CSV; агент действует в рамках `allowed_fields` и `usage_limits` — других возможностей в коде нет.

### 3.2. Запреты
- Парсинг сайтов без разрешения исключён архитектурно: «собрать» можно только из реестра.
- Никаких кэшей, зеркал, агрегаторов без письменного разрешения владельца данных.

## 4. ИИ-агент (Timeweb) — интеграция

Абстракция `AgentAdapter` — единственная точка взаимодействия с агентом. Параметры (эндпоинт, ключ, модель) — в `settings`.

### 4.1. Задачи, которые приложение отправляет агенту
1. **`collect_prices`** — сбор из `approved` источника:
   - вход: `source_id`, ограничения (`allowed_fields`, `price_date`, лимит строк);
   - выход: структурированные цены (JSON/CSV) → конвейер загрузки (валидация → нормализация → сопоставление).
2. **`match_suggest`** — рекомендации по сопоставлению для спорных пар (`pending`):
   - вход: кандидаты + каталог;
   - выход: пара + `confidence` + **обоснование** (почему это тот же товар).
   - Запрещено: агент не может предложить связь, которая в чёрном списке `rejected`.
3. **`analyze_prices`** — рекомендации по отклонениям и закупке:
   - выход: для конкурентов — «где мы дороже > N%», предложение целевой цены;
   - выход: для поставщиков — у кого дешевле закупка, предложение переключения.

### 4.2. Контракт и аудит
- Все вызовы агента логируются в `agent_log` (задача, источник, время, статус, результат/ошибка).
- Гейт согласия перед запуском агента на источник остаётся: чекбокс «Запустить сбор из <источник> в рамках его условий» — не предзаполнен.
- При сбое агента данные не теряются: статус, частичный результат и сообщение об ошибке сохраняются в `loads`.
- Агент **не меняет** каталог и `own_price` напрямую — только выдаёт рекомендации, применяет их владелец вручную.

## 5. Схема БД (SQLite)

```
products         id, sku UNIQUE, name, category, own_price REAL (RUB), is_active, updated_at

sources          id, name, scope, kind, origin_url, terms_hash, allowed_fields,
                 usage_limits, min_refresh_minutes, requires_attribution,
                 status, approved_at, review_period_days

loads            id, source_id?, scope, kind, file_hash?, file_name, started_at,
                 finished_at, status(running|success|partial|failed),
                 total_rows, ok_rows, error_rows, errors_summary, run_by(agent|manual)

prices           id, product_id, source_id, load_id, price REAL (RUB), price_date DATE,
                 external_key, raw_name,
                 UNIQUE(source_id, external_key, price_date)   -- идемпотентность

mappings         id, product_id, external_key, external_name,
                 method(exact|fuzzy|manual), similarity,
                 status(auto|pending|confirmed|rejected),
                 ai_recommended BOOL, reviewed_at

recommendations  id, product_id, source_id, rec_type(price_change|source_switch|match),
                 payload TEXT(JSON), status(proposed|applied|dismissed), created_at

agent_log        id, task, source_id, started_at, status, request_hash?, error

settings         key/value: auto_threshold, manual_threshold, deviation_threshold_pct,
                 agent_endpoint, agent_key, …
```

Целостность: `prices` append-only; уникальный ключ исключает дубли при повторной загрузке.

## 6. Архитектура

```
Streamlit UI
├─ Каталог | Загрузка | Сопоставление | Отчёт: конкуренты | Прайсы: поставщики | История | Настройки

core/       normalize · match · report · suppliers · history
services/   loads · sources · agent (AgentAdapter→Timeweb)
storage/    SQLite
```

- ИИ-агент подключается через `services/agent.py` (адаптер), все задачи идут через него, всё логируется.
- Полный процесс загрузки одинаков для CSV, API и результата агента: один конвейер `validate → normalize → match → store`.

## 7. Сценарии пользователя и userflow

### S1. Загрузка CSV (конкурент или поставщик)
1. Экран **Загрузка** → выбор контура (конкуренты/поставщики), источника из реестра или «Разовый файл».
2. Файл (.csv/.xlsx ≤20 МБ, ≤50 000 строк, UTF-8/cp1251, предпросмотр 5 строк).
3. Валидация → нормализация → сопоставление → снапшот на `price_date`.
4. Итог: `total/ok/error`, список ошибок по строкам. Спорные пары `pending` → экран сопоставления; в историю/отчёт — после подтверждения.

### S2. Сбор через ИИ-агента (API/фид)
1. Выбор `approved`-источника → подтверждение рамок условий.
2. Агент собирает (с учётом `min_refresh_minutes`; повторный запуск раньше интервала заблокирован).
3. Результат агента проходит тот же конвейер, что и CSV. Сбой агента = `loads.status=failed` + лог, история не трогается.

### S3. Сопоставление с ИИ-подсказками
1. Экран **Сопоставление**: список `pending`-пар.
2. Система показывает рекомендацию агента (`ai_recommended=1`) с обоснованием.
3. Владелец выбирает товар из каталога → **Подтвердить** / **Отклонить**.
4. Отклонённая пара уходит в чёрный список и больше не предлагается ни системой, ни агентом.

### S4. Отчёт по отклонениям (конкуренты)
Порог N% (слайдер, приходит из settings, клэмп 0–100). Показываются **только** позиции, где конкурент дешевле на ≥ N%. Колонки: SKU, товар, наша цена, цена конкурента, источник, дата, Δ% (красный) и Δ₽. Фильтры: категория, источник, период. Экспорт CSV. Плюс блок «Рекомендации агента» по каждой позиции.

### S5. Прайсы поставщиков
1. Экран **Прайсы**: выбор товара (или категории) → таблица всех поставщиков: последняя цена, мин/макс/средняя по периоду, диапазон дат.
2. Сравнение: для каждого товара — поставщик с минимальной ценой, разница с текущим.
3. История закупочной цены по поставщику (график) и рекомендации агента («дешевле у поставщика X на Y%»).

### S6. История цены товара
График `price vs date`, точки окрашены по источнику (легенда = источник), ховер с датой/ценой/источником; таблица рядов с обязательными колонками `source.name` и `price_date`.

### S7. Каталог и настройки
- Каталог: SKU обязателен и уникален, `own_price ≥ 0`, редактирование не трогает историю цен.
- Настройки: пороги сопоставления (`manual < auto`, оба 0–100), порог отчёта N%, параметры агента; только владелец (других пользователей нет).

## 8. Нормализация и сопоставление

1. **Точный SKU** (после нормализации) → `method=exact`, `status=auto`.
2. **Фаззи (RapidFuzz token_set_ratio)**: ≥90% и единственный кандидат → auto; 70–90% → `pending` (подтверждение владельца); <70% → «не сопоставлено».
3. **Ручное сопоставление** и **рекомендация агента** (с обоснованием) для спорных.
4. Чёрный список `rejected` приоритетнее любой рекомендации.

RUB everywhere: `price REAL` = рубли; валюта из файла, отличная от рубля, — ошибка валидации строки.

## 9. Порог отклонения

`deviation_pct = (competitor_price − own_price) / own_price × 100`; в отчёт попадают `deviation_pct ≤ −N`. N — в настройках и на экране отчёта (временный оверрайд, слайдер 0–100). Показывается и Δ₽. Отклонение считается только по товарам с активным `mapping.status` (`confirmed|auto`).

## 10. UI: элементы и их ограничения

- **Роль одна** — экран настроек не делим.
- **Контур** в Загрузке и Отчёте: селектор «Конкуренты / Поставщики» — определяет scope таблицы (одинаковые виджеты, разные данные).
- **Загрузка**: `file_uploader` только `.csv`, `.xlsx`; ≤20 МБ, ≤50 000 строк; кодировка UTF-8 (BOM)/cp1251 автодетект; предпросмотр 5 строк, подсветка невалидных; кнопка запуска неактивна до валидации файла.
- **Сбор**: кнопка запуска агентом блокируется при `expired`/`blocked` источнике или раньше `min_refresh_minutes`; индикатор «следующая попытка через …».
- **Сопоставление**: блок рекомендации агента (обоснование, до ~300 символов), для каждой `pending`-строки обязательны кнопки **Подтвердить/Отклонить**; пагинация.
- **Отчёт**: слайдер порога N% (0–100, шаг 1, клэмп), показано «X из Y позиций», фильтры (категория/источник/период) + сброс, экспорт CSV, сортировка по Δ%.
- **Прайсы (поставщики)**: таблица «товар × поставщик» (последние цены), автодополнение при выборе товара, пустое состояние «нет сопоставленных цен у N поставщиков».
- **История**: выбор товара с автодополнением, график с точками по источникам, таблица рядов с колонками source/дата; пустое состояние «Нет данных за период».
- **Каталог**: SKU обязателен и уникален, `own_price ≥ 0`, валидация до сохранения; редактирование не конфликтует с историей.
- Валютные подписи «₽» везде; выбора валюты в UI нет.
- Индикаторы работы агента: статус «идёт/успех/частично/неудача» + ссылка на запись `loads`. Ошибки не прерывают сессию.

## 11. Анти-паттерны (чёрный список)

| Риск | Решение |
|---|---|
| Парсинг без разрешения | Реестр источников §3, агент подключается только к `approved`, чекбокс согласия, лог всех вызовов |
| Дубли при повторной загрузке | `UNIQUE(source_id, external_key, price_date)` + контроль `file_hash` |
| Нечёткое сопоставление связывает разные товары | Точный SKU → фаззи с высокой планкой → `pending` → подтверждение; `rejected` в чёрном списке |
| Ошибки загрузки/сбоя агента затирают историю | `prices` append-only, транзакции, частичный импорт изолирован |
| Источник без атрибуции | `requires_attribution` → колонка источника обязательна |
| Агент выходит за рамки источника | Агент получает только `allowed_fields`/`usage_limits`; всё логируется в `agent_log` |

## 12. Критерии готовности

- ✔ Источник и дата цены видны в истории и отчётах.
- ✔ Ошибки загрузки и сбои агента не затирают историю.
- ✔ Условия использования соблюдены: реестр, сроки, чекбокс, аудит агента.
- ✔ Отчёт показывает только отклонения выше порога.
- ✔ Спорные сопоставления требуют подтверждения владельца; рекомендации агента — не решения.
- ✔ Прайсы поставщиков собираются и сравниваются отдельным контуром.

2. Прайсы поставщиков — сопоставляются с тем же каталогом `products`, или у поставщиков свой справочник товаров?

4. «Разовый файл без реестра» — оставляем? (При строгой политике источников это окно легального CSV.)
