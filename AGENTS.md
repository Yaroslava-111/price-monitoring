# AGENTS.md

## Проект

«Ценовой мониторинг: конкуренты + поставщики» — локальное однопользовательское приложение для владельца бизнеса.
Два контура данных: **конкуренты** (розничные цены, отчёт по отклонениям) и **поставщики** (закупочные прайсы, сравнение).
Сбор и разбор данных, а также рекомендации выполняет ИИ-агент (Timeweb), владелец подтверждает спорные сопоставления.

Подробное ТЗ: `ТЗ.md` (читать перед началом работы).

## Стек

- Python 3.11+
- Streamlit (UI)
- SQLite (хранение)
- Pandas (обработка)
- RapidFuzz (нечёткое сопоставление)
- Plotly (графики истории цен)
- Адаптер для ИИ-агента (Timeweb) через `services/agent.py`

## Железные правила проекта

1. **Сбор данных только из разрешённых источников.** Источник должен быть в реестре (`sources`) со статусом `approved`. Парсинг сайтов без разрешения запрещён архитектурно. Никаких кэшей/зеркал/агрегаторов без письменного разрешения.
2. **Целостность истории.** `prices` — append-only. Ошибки загрузки и сбои агента никогда не затирают и не меняют историю.
3. **Идемпотентность загрузки.** Уникальный ключ `(source_id, external_key, price_date)` + контроль `file_hash` — повторная загрузка не дублирует данные.
4. **Сопоставление.** Точный SKU = auto. Фаззи ≥90% (один кандидат) = auto. 70–90% = `pending`, требует подтверждения владельца. <70% = «не сопоставлено». Отклонённые пары (`rejected`) — в чёрный список, не предлагаются снова.
5. **Отчёт только по отклонениям выше порога N%.** `deviation_pct = (competitor_price − own_price) / own_price × 100`; фильтр на уровне SQL-запроса, не в UI.
6. **Источник и дата цены видны всегда** (колонки source.name и price_date) — требование requires_attribution.
7. **Единственная роль — Владелец.** Без логина/пароля. Валюта — только рубли (RUB). Уведомлений нет.
8. **Рекомендации агента — не решения.** Агент не меняет каталог и own_price напрямую; спорные пары подтверждает владелец вручную.

## Структура проекта

```
ТЗ.md             — техническое задание
app/
  main.py         — входная точка Streamlit
  ui/             — экраны: Каталог, Загрузка, Сопоставление,
                    Отчёт (конкуренты), Прайсы (поставщики), История, Настройки
  core/           — normalize.py, match.py, report.py, suppliers.py, history.py
  services/       — loads.py, sources.py, agent.py (AgentAdapter → Timeweb)
  storage/        — SQLite: db.py, repositories.py
db/               — файл БД (gitignore)
requirements.txt
```

- UI не делает SQL напрямую; во `время` запроса данные из SQLite читаются через `services/storage`, трансформации — через `core/`.
- Единый конвейер загрузки для CSV, API и результата агента: `validate → normalize → match → store`.

## Запуск и разработка

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
streamlit run app/main.py
```

Использование `npm`, установка новых Python-пакетов или любого ПО — только с явного разрешения Ярославы (глобальное правило).

## Соглашения

- Доллар/цена везде в рублях (формат с символом ₽).
- Новые таблицы/поля БД — только через миграции в `storage/db.py`, не редактировать схему напрямую.
- AI-агент вызывается только через `AgentAdapter` в `services/agent.py`; все вызовы логируются в `agent_log`.
- Репозиторий — git. Коммиты по явной просьбе пользователя.
